# apps 플러그인 패치노트

버전이 바뀔 때마다 맨 위에 한 덩어리를 덧붙인다(`/apps:config` "바꿀 때마다"). 이미 쓴 내용은 고치지 않는다.

- **버전 규칙**(2026-11-18 사용자 결정): 스킬을 추가하거나 스킬이 완성되면 가운데 수치(0.3.x → 0.4.0), 만드는 중인 스킬을 고칠 때마다 마지막 수치만(0.4.1, 0.4.2, …)
- **덩어리 형식**: `## 버전 — 날짜 · PC · 커밋` 아래에 해당하는 것만 쓴다
  - **추가** — 새 스킬(무엇을 하는 스킬인지, 추가 사유)과 새 기능
  - **변경** — 어느 스킬의 어느 부분이 어떻게 바뀌었나(바꾼 사유가 있으면 함께)
  - **버그 수정** — 어떤 문제가 있었고 어떻게 고쳤나

0.4.2 이전 내용은 2026-11-18에 git 기록과 `HANDOFF.md` 플러그인 행에서 되살려 적었다.

## 0.4.7 — 2026-11-23 · 사내망 PC

- **변경**
  - 인계 위치: 주제 폴더마다 인계 전용 **`HANDOFF.md`**(상태·인계·남은 일·진행 이력)를 둔다 — 진행 중 주제는 `_drafts/<주제>/HANDOFF.md`(README.md 대신), 완성된 앱은 `projects/apps/<앱>/HANDOFF.md`(앱 `CLAUDE.md`에는 규칙·명령과 링크만). **작업 하나를 끝낼 때마다** 인계를 고치고, **상태**를 들어올 때 "진행 중"·종료할 때 "종료"로 적어 "진행 중"이 남아 있으면 비정상 종료로 보고 인계 날짜 이후 커밋·커밋 안 한 변경부터 확인한다. 원본 규칙은 `projects/apps/CLAUDE.md` "주제 인계"(루트 CLAUDE.md 한 줄도). 사유: 도구(Zed)를 갑자기 끄면 대화 끝에만 고치던 인계가 비어 다음 진입 때 이어 갈 기준이 없어짐, 그리고 인계·이력이 앱 `CLAUDE.md`의 약 88%라 폴더를 건드릴 때마다 함께 읽힘(사용자 결정)
  - `selection-subject`: `HANDOFF.md`를 읽고 상태 확인·"진행 중" 기록·작업마다 인계 갱신, 종료 때 상태 "종료". "진행 중"이 남았을 때 상태 줄의 PC와 지금 PC(github.com 접속 가능 여부로 판단)가 같으면 비정상 종료로 보고 확인 후 진행, 다르면 pull 확인 뒤 먼저 묻는다
  - `new`: 주제 폴더의 `README.md` → `HANDOFF.md`, 작업마다 갱신·상태, 5단계에서 `HANDOFF.md`를 앱 폴더로 그대로 옮기고 `_drafts/README.md`의 "진행 중" 줄을 "완성"으로 옮겨 적음
  - 위 두 보완과 vocab 상태 줄 형식은 `/oh-my-claudecode:verify`(verifier, APPROVE)의 권고를 반영
  - `view-subjects`: `HANDOFF.md`에서 상태·인계·이력을 읽고, "진행 중"으로 남은 주제와 `HANDOFF.md`가 없는 앱을 어긋남으로 알림
  - vocab: `CLAUDE.md`의 인계·남은 일·진행 이력을 `projects/apps/vocab/HANDOFF.md`로 줄 그대로 옮김(165줄 → `CLAUDE.md` 약 45줄)
