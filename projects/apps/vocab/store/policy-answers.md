# Vocara — Play Console "앱 콘텐츠" 답안 초안

Play Console → 정책 → 앱 콘텐츠의 항목마다 답과 근거를 적었다. 2026-11-28 개인 PC에서 코드로 확인한 사실이 근거다. **설문 문항의 실제 문구는 등록할 때 화면에서 다시 읽고 고른다** — 여기 문항 이름은 Play Console 화면을 직접 보지 않고 적은 것이다.

## 근거로 쓴 앱 사실

| 사실 | 확인한 곳 |
|---|---|
| 인터넷 권한이 없다 — 데이터를 밖으로 보낼 수 없다 | release 병합 매니페스트(`build/app/intermediates/merged_manifests/release/processReleaseManifest/AndroidManifest.xml`, 2026-11-28 일일 학습 뒤)의 `uses-permission`: `POST_NOTIFICATIONS`(매일 알림)·`RECEIVE_BOOT_COMPLETED`(재부팅 뒤 알림 다시 예약)·`VIBRATE`(알림 패키지가 넣음)·`kr.msjin.vocab.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`(AndroidX 내부) — `INTERNET` 없음, 정확한 알람 권한 없음 |
| 계정·로그인 없음 | 앱에 로그인 화면·인증 패키지 없음(`pubspec.yaml` 의존성: flutter_tts, sqflite, path, go_router, flutter_riverpod, shared_preferences, flutter_local_notifications, timezone) |
| 기록은 기기 안에만 | sqflite(`lib/data/` 학습·시험·오답·단어장·오늘의 단어 `daily_words`), shared_preferences(고른 단어장, 매일 알림 켜짐·시각) |
| 알림은 기기 안 예약 | `flutter_local_notifications`의 로컬 예약 알림(`lib/features/reminder/`) — 서버 푸시·Firebase 없음 |
| 광고·분석 SDK 없음 | `pubspec.yaml`에 광고·분석·Firebase 패키지 없음 |
| 결제 없음 | 결제 패키지 없음 |
| 발음은 기기 TTS | `flutter_tts`, 매니페스트 `<queries>`의 `TTS_SERVICE` |
| 단어에 민감한 말이 사전적 뜻으로 있다 | 심화 칸 `assets/words/advanced_*.json` — 예: damn "(욕설) 빌어먹을", bloody "(영국 욕설) 빌어먹을", hell "지옥, (비속어로 쓰여) 도대체·젠장", gook "(아시아인을 낮잡는) 인종 비하어", retard "늦추다, 지체 장애인을 낮춰 부르는 욕", rape "강간, 성폭력", sexual "성적인, 성과 관련된" 등 25개(4차 5단계 사용자 결정 "다 넣는다", HANDOFF 인계) |

## 1. 개인정보처리방침

- 답: Google Sites에 게시한 `privacy-policy.md`의 주소 → `{처리방침 주소}`

## 2. 광고

- 답: **아니요, 앱에 광고가 없습니다**

## 3. 앱 액세스 권한

- 답: **모든 기능을 특별한 액세스 권한 없이 이용할 수 있음**(로그인·구독·위치 제한 없음)

## 4. 콘텐츠 등급(IARC 설문)

- 카테고리: **참고 자료, 뉴스 또는 교육**에 가까운 항목(설문 첫 화면의 분류에서 고른다)
- 폭력·공포·도박·약물·성적 콘텐츠를 **보여 주거나 묘사하는 장면은 없다** — 이미지·영상 없이 단어와 예문뿐
- **언어(욕설·비속어)와 차별적 표현**: 위 표처럼 심화 칸 단어장에 욕설·비하어가 **사전적 뜻과 함께** 들어 있다. 숨기지 말고 해당 문항에 **있음**으로 답하는 것을 권한다(사전·교육 목적이라는 설명란이 있으면 그렇게 적는다)
  - **주의(사용자 결정 필요)**: 이 답 때문에 등급이 전체 이용가보다 올라갈 수 있다(예: 12세 이상). 13세 미만을 대상에 넣은 것(5절)과 맞지 않게 나오면, 등록 전에 ① 등급을 받아들이기 ② 해당 말을 빼기(새 DB 판 필요 — 심화를 연 뒤라 번호가 바뀜) ③ 심화를 13세 이상 단어장으로 따로 두기 중에서 정한다. 어떤 등급이 나올지는 설문을 실제로 해 봐야 안다(확인하지 않음)
- 사용자 간 소통·공유·위치 공유·디지털 상품 구매: **없음**

## 5. 타겟층 및 콘텐츠

- 대상 연령: **5세 이하는 빼고, 6~8 · 9~12 · 13~15 · 16~17 · 18세 이상**(초등 단어부터 있으므로) — 13세 미만이 들어가므로 **가족 정책**을 따른다
- 앱이 아동의 관심을 끌 만한가: 학습 앱 — 위 대상 연령을 고르면 자동으로 가족 정책 대상이 된다
- 가족 정책에서 확인할 것: 광고 없음, 개인정보 수집 없음, 위치·기기 식별자 수집 없음 → 모두 해당 없음
- "교사 승인" 배지 신청은 선택 — 이번 범위 밖

## 6. 데이터 보안

- 앱이 사용자 데이터를 수집하거나 공유하는가: **아니요**
  - 근거: 인터넷 권한이 없어 기기 밖으로 보낼 수 없다. 매일 알림도 기기 안에서 예약하는 로컬 알림이라 데이터 전송이 없다(알림 권한은 데이터 보안 양식의 "수집" 대상이 아니다 — 알림을 보이게 하는 권한일 뿐). Play 정의상 "기기에서만 처리되고 밖으로 전송되지 않는 데이터"는 수집으로 보지 않는다(이 정의는 Play 도움말 기준으로 알고 있는 내용 — 등록 때 화면 설명을 다시 읽고 확인)
- 데이터 암호화·삭제 요청 문항: 수집이 "아니요"면 보통 묻지 않는다. 묻는다면 "앱 삭제로 모든 기록이 지워진다"(처리방침 3절)

## 나중에 광고를 넣을 때 (2026-11-28 메모 — 지금은 광고 없음)

새로 등록하지 않고 업데이트로 넣는다. 13세 미만이 대상에 있으므로:

1. **가족용 인증 광고 SDK만** 쓴다(Google Play "가족 정책 자체 인증 광고 SDK" 목록 — AdMob은 해당). 어린이 대상 처리(child-directed) 설정을 켜야 하고 **맞춤 광고는 안 된다**
2. 앱: 광고 SDK와 인터넷 권한 추가, 광고 자리
3. Play Console: 2절 광고 → "예"(스토어에 "광고 포함" 표시), 6절 데이터 보안 다시 작성(광고 SDK가 다루는 기기 식별자 등), 5절 가족 정책 다시 확인 → 심사
4. 문서: `privacy-policy.md`의 1·2·4절, `listing.md`의 "광고 없음"·"외부로 보내지 않습니다" 줄을 고친다

위 1~3은 알고 있는 Play 정책을 정리한 것이고 2026-11-28에 공식 문서로 다시 확인하지는 않았다. 광고를 넣기 전에 Play 가족 정책 도움말을 확인한다.
