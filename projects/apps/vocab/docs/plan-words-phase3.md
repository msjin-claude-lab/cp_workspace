## 설계 결정

- **단계 파일 `tiers-high.csv`**(단어, 단계, 이유, 난이도) — 후보 2,728줄 전부
  - 단계 `1 · 2 · 3` = 한국 고등학교(공통영어 수준)에서 먼저 배울 순서. **`4` = 심화로 미룸**(전문 분야 말, 드문 격식어 — B1에만 쓴다. 맨 뒤로 가므로 고등에 들지 않는다). **`x` = 어느 칸에도 넣지 않음**(욕설·성적 표현만 — 사용자 확인 뒤. 없으면 0줄)
  - A1·A2 줄은 전부 뽑히므로 **단계는 기록용**이다(뽑기에 쓰이지 않는다). `4`는 금지, `x`는 사용자 확인을 받은 것만. 중등에서 단계 4였던 학술어 66개와 `x`였던 9개도 고등에 들어간다 — 스크립트가 "중등 `x` 9개가 여기서 `x`가 아님"을 검사한다
  - 뽑기: A1·A2 전부 + B1을 `(단계, 빈도 순위, 알파벳)` 순으로 세워 1,500개가 될 때까지. **뽑힌 것 중 단계 4가 있으면 종료 코드 1**(B1의 단계 1~3이 854개보다 적다는 뜻 — 단계를 다시 매긴다)
  - 난이도 열은 **뽑힌 1,500개만** 1·2·3이 있어야 한다. 뽑히지 않은 B1 줄의 난이도는 어디에도 쓰이지 않으므로 비워도 되고, 적었다면 1·2·3이어야 한다(`select.py:323`의 검사를 고등에서는 뽑힌 줄로 좁힌다 — 4차에서 다시 매긴다)
  - 칸 배정: 뽑힌 1,500개를 `(난이도, 빈도 순위, 알파벳)`으로 세워 앞에서부터 500 · 500 · 500. 난이도 `1` 쉬움(고1 — 일상·일반 말) · `2` 중간 · `3` 어려움(추상어, 학술·격식 말, 뜻이 여럿인 말). **중등 때의 난이도를 그대로 가져오지 않고 고등 기준으로 다시 매긴다**(중등에서 3이던 말이 고등에서는 1일 수 있다)
- **다시 만들어도 같은 결과**(2차 규칙 그대로): 고등 단계는 커밋된 csv에서만 읽는다 — 거를 단어는 `elementary.csv`·`middle.csv`. `overlap.csv`의 고등 줄은 거르지 않는다(지우는 단어라 후보로 돌아온다). 산출물은 `candidates-high.csv`·`tiers-high.csv`·`high.csv`만 쓴다. 초등·중등을 다시 돌려도 csv가 그대로여야 한다
- **번호**: `high.csv` 순서대로 `w-1501`~`w-3000`(`cells.py`의 첫 번호 = `elementary.csv` + `middle.csv` 줄 수 다음)
- **DB 10판**: 표는 그대로, 옛 고등 번호(`he-`·`hm-`·`hh-`)의 `study_log`·`quiz_log`·`wrong_notes` 줄을 지운다. 고등 칸으로 만든 단어장 줄(`study_decks`)은 남긴다(9판과 같은 방식, `_deleteWordIds` 재사용)

## 단계

### 1. 선정 스크립트에 고등을 더한다
- `select.py --stage high`: 위 "다시 만들어도 같은 결과" 규칙. 검사(어긋나면 종료 코드 1) — 칸 개수 500 · 500 · 500, 중복 0, 초등·중등과 겹침 0, 단계 파일과 후보가 정확히 맞음, A1·A2에 `4`가 없음, 중등 `x` 9개가 `x`가 아님, 뽑힌 것에 단계 4가 없음, 뽑힌 줄은 난이도 1·2·3. 출력: B1이 어느 단계 몇 번째까지 뽑혔는지와 뽑힌 1,500개의 난이도 분포
- `cells.py --stage high`(기준 `high.csv`, 첫 번호 `w-1501`)
- 두 파일의 머리 설명, README "만드는 법"·파일 표
- 원본 두 파일을 받는다. `select.py`가 두 파일의 SHA-256을 README 값과 비교해 다르면 종료 코드 1로 멈추게 한다(지금은 `:193`·`:373`에서 출력만 한다)
- 완료 기준: `echo "<README 값>  <zip>" | sha256sum -c && echo "<README 값>  <txt>" | sha256sum -c &&` `python tool/wordlist/select.py --stage elementary --cefrj <zip> --freq <txt> && python tool/wordlist/select.py --stage middle --cefrj <zip> --freq <txt> && git diff --exit-code -- 'docs/wordlist/*.csv'` 종료 코드 0, `--stage high`가 `candidates-high.csv`를 쓰고 후보 수(위 계산값 2,728과 다르면 이 문서의 숫자를 고친다)를 출력

### 4. 뜻·예문·해석을 쓴다 (1,500개)
- **첫 커밋에서 옛 고등 150개를 지운다**(세 파일을 빈 목록으로)
- **칸은 한 번에 하나씩 쓴다**(쉬움 → 중간 → 어려움). `cells.py check`·`word_assets_test`·`similar_words_test`가 다른 칸까지 읽고, `similar_words.dart`·`HANDOFF.md`·git 색인을 함께 쓰기 때문이다
- 칸마다 **100개 묶음 5개**. `executor`가 쓰고 묶음마다 `python tool/wordlist/cells.py --stage high check && flutter test test/data/word_assets_test.dart test/data/similar_words_test.dart && git add assets/words/high_<칸>.json lib/data/similar_words.dart HANDOFF.md && git commit`(`wip:`, 경로를 밝혀서) 뒤 push
