# projects/apps — 앱 공통 규칙

앱 작업은 **이 파일을 기준으로 시작한다.** 루트 `CLAUDE.md`(망·git·답변 형식 등 공통 규칙)는 항상 함께 적용된다.

## 시작하는 법

- Claude Code는 **저장소 루트**에서 연다(앱 폴더에서 열면 HUD·hook 설정이 빠진다 — 루트 CLAUDE.md "앱을 여러 개 만들 때")
- 첫 입력: `projects/apps/CLAUDE.md 를 읽고 앱 작업을 이어서 한다.` — 또는 `/apps:new <앱 아이디어>`(이 파일을 읽고 "지금 상태"의 단계를 진행하는 스킬, `plugins/apps/skills/new`)
- 읽은 뒤 아래 **"지금 상태"**의 단계부터 이어 간다. 단계 하나를 끝낼 때마다 "지금 상태"를 고치고, 자세한 기록은 루트 `HANDOFF.md`의 "앱" 절에 남긴다

## 지금 상태

- 단계: **1. 만들 앱을 정한다** — 후보로 이야기된 것: 캘린더형·기록형 앱(먼저), 게임형 앱(나중). 아직 정하지 않음
- 마지막 갱신: 2026-11-17 (사내망 PC)

## PC 역할

- **개인 PC**: 전부 — 코드 수정, SDK 설치, 빌드, 기기·에뮬레이터 테스트
- **사내망 PC**: 코드 수정·코드 점검까지만(`github.com` 차단, SDK·빌드 미확인). 여기서 한 작업은 "수정만 함, 개인 PC에서 테스트 필요"로 기록한다
- 그래서 4단계(검증)는 **개인 PC에서만** 한다

## 새 앱을 시작하는 순서 (2026-11-17 사용자 결정)

언어·플랫폼(Flutter, React Native 등)을 먼저 정하지 않는다. 아래 순서를 건너뛰지 않는다.

1. **만들 앱을 정한다** — 기능, 화면, 데이터, 대상 플랫폼(안드로이드·iOS 등)
2. **선택안을 제시한다** — 그 앱에 맞는 언어·플랫폼 후보를 장단점과 함께
3. **사용자가 고른다**
4. **검증한다** — 개인 PC에서 설치·빌드·간단한 시험으로 실제로 되는지 확인
5. **최종 결정한 뒤 진행한다** — 그때 `projects/apps/<앱>/`과 그 앱의 `CLAUDE.md`(빌드·테스트 명령)를 만든다
