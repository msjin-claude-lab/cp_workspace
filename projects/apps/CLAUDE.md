# projects/apps — 앱 공통 규칙

앱 작업은 **이 파일을 기준으로 시작한다.** 루트 `CLAUDE.md`(망·git·답변 형식 등 공통 규칙)는 항상 함께 적용된다.

## 시작하는 법

- Claude Code는 **저장소 루트**에서 연다(앱 폴더에서 열면 HUD·hook 설정이 빠진다 — 루트 CLAUDE.md "앱을 여러 개 만들 때")
- 주제 목록·진행 보기: `/apps:view-subjects` (주제를 주면 자세히: `/apps:view-subjects vocara`)
- 주제 골라 이어 가기: `/apps:selection-subject [주제]` (주제 없이 부르면 목록 + 신규 주제 시작)
- 새 주제 시작: `/apps:new <주제>`
- 개발 환경: 공통은 [SETUP.md](SETUP.md)(Flutter·Android SDK 설치·확인·함정), 주제별은 `_drafts/<주제>/setup.md`(그 앱의 패키지·설정·가상 기기). 5단계에서 앱 폴더 `SETUP.md`로 옮긴다
- 앱: [vocara](vocara/CLAUDE.md)(영단어 앱 Vocara — 2026-11-29 폴더 이름을 vocab에서 바꿈, Flutter, 2026-11-19 앱 폴더 생성). 앱 작업은 그 앱 [HANDOFF.md](vocara/HANDOFF.md)의 "인계"부터 읽는다

## 주제별 기록 — `_drafts/<주제>/` (2026-11-18 사용자 결정)

이 파일에는 **공통 규칙만** 둔다. 개별 주제(앱 후보)의 내용과 진행 상태는 주제 폴더 `projects/apps/_drafts/<주제>/`에 둔다(`HANDOFF.md` 진행 상태, `spec.md`, `options.md`, `verify.md`). 진행 중인 주제와 후보 목록은 [_drafts/README.md](_drafts/README.md).

## 주제 인계 — 주제 폴더의 `HANDOFF.md` (2026-11-18 사용자 결정, 2026-11-23 전용 파일로 바꿈)

주제 = 앱(프로젝트). 진행 상태는 **주제 폴더 안의 `HANDOFF.md` 한 곳**에 둔다 — 진행 중 주제는 `_drafts/<주제>/HANDOFF.md`, 완성된 앱은 `projects/apps/<앱>/HANDOFF.md`(5단계에서 그대로 옮긴다). 앱 `CLAUDE.md`에는 규칙·명령·코드 구조와 이 파일 링크만 둔다(그 폴더를 건드릴 때마다 자동으로 읽히므로 가볍게 유지한다). 루트 `HANDOFF.md`에는 주제마다 링크와 한 줄만.

`HANDOFF.md`의 절:
- **상태** 한 줄: `- 상태: 진행 중 · 날짜 시각 · PC` 또는 `- 상태: 종료 · 날짜 · PC`. PC는 **`사내망 PC` 또는 `개인 PC`** 둘 중 하나로만 적는다(들어올 때 비교하는 값이다. 지금 PC는 `github.com` 접속 가능 여부로 안다 — 막혀 있으면 사내망 PC, 루트 CLAUDE.md "네트워크 제약")
- **인계**: 지금 단계(날짜·PC) / 멈춘 곳 / 다음 할 일(입력할 명령까지) / 주의할 것. 늘 지금 기준으로 고쳐 쓴다
- **남은 일**: 다음 할 일 뒤의 큰 일
- **진행 이력**: 덧붙이기만 한다. `- 날짜 PC · 종류 · 한 일과 결과 한 줄`

규칙:
- **작업 하나를 끝낼 때마다 인계를 고치고 이력에 한 줄 덧붙인다.** 대화를 마칠 때까지 미루지 않는다 — 도구를 갑자기 꺼도 잃는 범위가 작업 하나로 줄어든다. 단계가 끝나지 않았어도, 스킬을 쓰지 않은 작업이어도 한다
- **주제를 시작·재개하면 상태를 "진행 중"으로, 종료하면 "종료"로 적는다.** 들어올 때 "진행 중"이 남아 있으면 상태 줄의 PC와 지금 PC를 비교한다
  - **같은 PC** → 지난번이 정상 종료되지 않은 것이다. 인계 날짜 이후의 git 커밋과 그 폴더의 커밋 안 한 변경을 먼저 보여 주고, 인계에 반영한 뒤 이어 간다
  - **다른 PC** → 그 PC에서 아직 진행 중이거나 그 PC가 정상 종료하지 못한 것이다. `git pull`로 최신을 받았는지 확인하고, 위와 같이 보여 준 뒤 이어서 할지 사용자에게 묻는다
  - 한계: 같은 PC에서 대화 두 개가 같은 주제를 동시에 진행하면 구분하지 못한다(세션 구분 정보가 없다) — 한 주제는 한 대화에서만 진행한다
- **새 세션에서 주제를 진행할 때는 무조건 그 "인계"부터 읽고, 그 내용을 기준으로 이어 간다.** 인계와 실제 파일·git 이력이 다르면 진행하기 전에 사용자에게 알린다

## PC 역할

- **개인 PC**: 전부 — 코드 수정, SDK 설치, 빌드, 기기·에뮬레이터 테스트
- **사내망 PC**: **가능한 데까지 개인 PC와 똑같이 진행하고, 한 것은 공유한다**(2026-11-18 사용자 결정 — 사내망 PC에 Flutter·Android SDK를 설치해 `flutter build apk`까지 됨). 할 수 없는 것만 "확인 못 함"으로 남기고 개인 PC에서 마저 한다 — 지금은 github.com에서만 받는 파일([projects/SETUP.md](../SETUP.md)), 소리 듣기(사무실), 에뮬레이터 실행 확인(아래 규칙). 에뮬레이터 자체는 2026-11-19부터 사내망 PC에서도 뜬다(WHPX 켬, [SETUP.md](SETUP.md))
- **에뮬레이터 실행 단계는 개인 PC에서만 한다(2026-11-23 사용자 결정)**
  - **개인 PC**: 작업 순서에 에뮬레이터 실행(설치 → 화면 확인)을 **포함한다**
  - **사내망 PC**: 에뮬레이터 실행 단계를 **넣지 않는다** — analyze·test·build까지만 하고, 건너뛴 실행 확인은 그 주제 `HANDOFF.md` 인계에 "에뮬레이터 확인 안 함, 개인 PC에서 필요"로 무엇을 볼지와 함께 남긴다
  - **나중에 개인 PC에서 그 주제를 진행할 때** 인계에 남은 에뮬레이터 확인을 **추가로 진행한다**(사내망 PC에서 만든 변경분까지 포함)
  - 사내망 PC에서도 에뮬레이터가 뜨기는 하지만(아래) 느려서 작업 단계로 쓰지 않는다
- 그래서 4단계(검증)도 **두 PC 모두에서 한다** — 사내망 PC는 위 규칙대로 에뮬레이터 실행을 뺀 범위까지. 결과는 PC를 밝혀 `verify.md`에 따로 적는다
- **기기 실행 확인은 에뮬레이터로만 한다 — 실제 폰은 연결하지 않는다**(2026-11-18 사용자 결정). 에뮬레이터는 Windows 하이퍼바이저 플랫폼(WHPX)이 켜진 PC에서만 뜬다(켜기: 관리자 PowerShell `Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform` + 재부팅). 대안으로 폰 연결을 권하지 않는다

## 새 앱을 시작하는 순서 (2026-11-17 사용자 결정)

언어·플랫폼(Flutter, React Native 등)을 먼저 정하지 않는다. 아래 순서를 건너뛰지 않는다.

1. **만들 앱을 정한다** — 기능, 화면, 데이터. 대상 플랫폼은 **안드로이드·iOS 둘 다**(모든 앱 공통, 2026-11-18 사용자 결정)
2. **선택안을 제시한다** — 그 앱에 맞는 언어·플랫폼 후보를 장단점과 함께
3. **사용자가 고른다**
4. **검증한다** — 개인 PC에서 설치·빌드·간단한 시험으로 실제로 되는지 확인
5. **최종 결정한 뒤 진행한다** — 그때 `projects/apps/<앱>/`과 그 앱의 `CLAUDE.md`(빌드·테스트 명령)를 만들고, 주제 폴더의 기록을 옮긴 뒤 `_drafts/<주제>/`를 지운다
